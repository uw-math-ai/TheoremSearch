# Lean Premise Retrieval & Retrieval-Augmented Formalization

Retrieve the formal premises a theorem depends on from a natural-language description, and
study whether injecting those premises helps a model **formalize** statements — especially
for libraries the model has never seen.

## What this is (and provenance)

The pipeline combines three inputs:

- **A dependency graph** — *lean-graph* (Evan Wang). It defines what counts as a premise
  (the `sig`/`extends`/`field` dependency edges of a declaration's *signature*), the
  forbidden sets (a target plus its transitive reverse-dependencies), and the project/module
  structure used for leakage-controlled splits.
- **Slogans + embeddings** — generated by the team's slogan pipeline (qwen3-235b natural-language
  "slogans" describing each formal statement; embedded with Qwen3-Embedding-8B, 4096-d). These
  live in the `v2` RDS database and are consumed **read-only** here.
- **Our retrieval + formalization pipeline** — a cosine retriever with a learned query head
  trained on the graph's premise labels, leakage-controlled evaluation, and a
  retrieval-augmented-formalization study. Moderately **inspired by** slszeto's `premise-rl`
  (env/reward shape, eval-harness layout), but it does **not** use that project's
  TheoremSearch-API + body-matching + GRPO core — we build our own retriever directly over the
  formal slogan embeddings.

This repo contains **only our code + reproduction instructions + result tables**. It does not
contain the slogans/embeddings/graph data (private; in `v2` RDS) or any credentials.

## Headline result

Does retrieval help formalization? It depends on whether the needed premises are inside the
model's training. See [`docs/RESULTS.md`](docs/RESULTS.md) for the full tables.

| setting | model | no-RAG | RAG | takeaway |
|---|---|---|---|---|
| Mathlib (familiar) | Qwen3-8B (weak) | 12.5% | 31.8% | retrieval helps weak models |
| Mathlib (familiar) | Sonnet (strong) | 83% | 75% | no help — model already knows the API |
| unfamiliar library, sandboxed | Sonnet (strong) | 0% | 50% | retrieval is decisive |
| unfamiliar library + search | Sonnet | 78% (search) | 78% (RAG+search) | RAG matches search at a fraction of the cost |
| large corpus, post-cutoff Mathlib | Sonnet | 21% | 33% | RAG ≥ library search (25%) at ~40% the cost |

(All numbers are **hand-judged correctness**, not typecheck rate. Typecheck rates, compute, and
the compiler-in-the-loop variants are in [`docs/`](docs/). The large-corpus row uses the
"high-confidence-equivalent" metric; see [`docs/large_corpus_results.md`](docs/large_corpus_results.md).)

## Pipeline / reproduction

Local steps need a Python env (`pip install -r requirements.txt`; CPU torch is fine) and a
`.env` (copy `.env.example`, fill in shared RDS credentials). GPU steps run on an L40S via the
vLLM apptainer image (see `klone/`). Lean typecheck needs a built Mathlib (and, for the
unfamiliar-library experiment, a built target library).

### A. Build the retrieval index and splits  (local + v2 RDS)
```
python scripts/build_formal_index.py      # pull 388k formal slogan embeddings -> cache/formal_emb.f16.npy + ids
python scripts/build_split.py             # module-held-out train/val/test + premise-frequency tables
```

### B. Retrieval experiments  (local)
```
python scripts/eval_similarity_baseline.py   # raw-cosine recall@k (the floor)
python scripts/eval_frequency_prior.py        # popularity-prior baseline + rarity buckets (control)
python scripts/train_supervised_full.py       # learned query head + train-size scaling curve
python scripts/eval_query_shuffle.py          # query-shuffle diagnostic (is the gain query-conditioned?)
```
`src/formal_retriever.py` is the retriever (cosine top-k with forbidden masking + optional query head).

### C. Retrieval-augmented formalization  (local build + GPU generate + local typecheck)
```
python scripts/build_formalization_eval.py    # eval set: slogan/informal -> (gold) formal statement
python scripts/build_rag_context.py           # attach retrieved premises to each target
# generate on the L40S (no-RAG vs RAG), inside the vLLM apptainer:
#   klone/run_frxgen.sbatch  ->  scripts/formalize_gen.py  (Qwen3 ladder)
python scripts/score_formalization.py         # typecheck rate + premise-grounding, RAG-vs-no-RAG delta
```
`scripts/run_typecheck.py` is the batched Lean+Mathlib well-formedness checker (one `import Mathlib`,
renames + wraps each statement, parses `error:` lines). Run its `--selftest` first.

### D. Unfamiliar-library experiment  (the strong-model result)
```
# extract the target library's decls (exact signatures + intra-library deps), run inside the built library:
lake env lean lean/extract_lib_decls.lean    # -> per-decl {name, sig, lib_deps}
# on the L40S: back-translate decls -> informal, embed -> library index:
klone/run_bm.sbatch  ->  klone/backtrans_and_embed.py
# retrieve (with forbidden masking) + formalize with a SANDBOXED model (no source access),
# then typecheck against the built library:
python scripts/typecheck_lib_outputs.py
```

## Important methodology

The experimental design needed two corrections that are themselves findings — read
[`docs/METHODOLOGY.md`](docs/METHODOLOGY.md) before extending this:
1. **Sandbox the formalizer.** A tool-enabled agent will read the library source (where the gold
   lives), invalidating any no-RAG/RAG comparison. The formalizer must not see the source.
2. **Mask forbidden premises.** Retrieval must exclude the target itself and its transitive
   reverse-dependencies, or it leaks the answer / circular premises.
